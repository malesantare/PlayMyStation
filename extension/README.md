# YouTube Music Connect

Расширение Manifest V3 для Chrome 120+ и совместимых Chromium-браузеров
(Edge, Brave, Яндекс Браузер — требуют проверки в конкретной версии).
Firefox, Safari и мобильные браузеры в этой версии не поддерживаются.

## Установка и подключение

1. Владелец бота разворачивает сервер с `/connect/youtube` из этой ветки.
   `PUBLIC_BASE_URL` должен содержать публичный HTTPS origin сервера, без пути.
   PostgreSQL, Redis и корректный `FERNET_KEY` обязательны. Для локальной
   диагностики разрешён `http://127.0.0.1:8000` или `http://localhost:8000`.
2. Скачай репозиторий, открой `chrome://extensions` (Edge: `edge://extensions`),
   включи режим разработчика, нажми «Загрузить распакованное расширение» и выбери
   папку `extension`, содержащую `manifest.json`.
3. Открой личный чат с ботом и отправь `/youtube_connect`.
4. Нажми значок расширения. Вставь сервер и одноразовый код из сообщения бота.
   Убедись, что доверяешь владельцу сервера, отметь согласие и нажми «Подключить».
   Разреши доступ только к указанному серверу в запросе браузера.
5. В новой вкладке YouTube Music войди в нужный Google-аккаунт и открой библиотеку.
   Для выбора другого аккаунта сначала войди в него, затем начни подключение заново:
   первый подходящий авторизованный запрос завершает сбор автоматически.
6. Вернись на страницу расширения: дождись «Подключено». В Telegram отправь
   `/youtube`, затем `/now`. Можно переподключить существующую интеграцию.

После передачи сбор прекращается. Для обновления cookies повтори шаги с новым
кодом. Постоянной фоновой синхронизации в этой версии нет. Расширение не опубликовано
в Chrome Web Store; установка пока только вручную.

## Как это устроено

- Бот выдаёт случайный код с 192 битами энтропии, TTL 10 минут. В группах код не
  выдаётся. Redis хранит его хэш; `GETDEL` разрешает только одну попытку привязки.
- Расширение наблюдает только запросы `/youtubei/v1/*` из созданной им вкладки
  `music.youtube.com`. До согласия пользователя данные не собираются.
- Chrome может скрывать Authorization. Расширение строит SAPISIDHASH по cookie
  и origin; сохраняет выбор аккаунта `x-goog-authuser` и brand ID, если они есть.
- Cookies идут в JSON напрямую серверу по HTTPS. Перенаправления запрещены,
  cookies браузера для сервера не прикладываются, произвольные заголовки отбрасываются.
- Сервер проверяет историю через существующий `ytmusicapi`, шифрует данные Fernet
  и сохраняет интеграцию пользователя, связанного с кодом. Клиент не задаёт Telegram ID.
- Код и состояние ожидания живут только в `chrome.storage.session`, не sync/local.
  Сами заголовки не записываются в хранилище расширения и не выводятся в консоль.
  Нажатие «Остановить», закрытие вкладки, истечение времени или завершение передачи
  прекращают ожидание. Уже доставленные серверу данные этим не удаляются.

Данные сессии дают доступ от имени пользователя: передавай их только своему
доверенному серверу. `/disconnect youtube` удаляет привязку в боте; для отзыва
скомпрометированной Google-сессии используй настройки безопасности Google.
Не отправляй cookies, код привязки и auth JSON в issues или скриншотах.

## Диагностика

- Нет успешного подключения: открой библиотеку или обнови новую вкладку, проверь
  вход в аккаунт, сетевую доступность сервера и `/ready`.
- Ошибка проверки или таймаут: код уже мог быть использован; получи новый
  `/youtube_connect`. Расширение намеренно не повторяет отправку автоматически.
- HTTP работает только на loopback; удалённому серверу нужен HTTPS.
- Расширение не решает ограничения Google OAuth, блокировки IP при скачивании,
  протухшие cookies или отсутствие истории. YouTube Music здесь отдаёт последний
  трек из истории, а не realtime-состояние плеера.

## Проверки разработчика

```sh
node --test extension/helpers.test.mjs
python -m pytest -q tests/test_browser_connect.py
```

Опциональная проверка в настоящем Chromium (отдельное тестовое окружение):

```sh
pip install playwright
python -m playwright install chromium
python scripts/check_extension_browser.py
```

Она использует временный профиль, локальный HTTPS-сервер вместо Google и
искусственные HttpOnly cookies. Проверяет UI → новую вкладку → перехват заголовков
→ единственную отправку. Временный manifest заранее разрешает loopback-доступ;
диалог выдачи разрешений реального браузера остаётся ручной проверкой.

Для ручной проверки используй отдельного бота и собственную Google-сессию.
Проверь успешную привязку, смену аккаунта, повторное использование/истечение кода,
отмену, закрытие вкладки и недоступный сервер. Автотесты не подтверждают реальный
вход в Google или успешное скачивание треков.

API браузера: [webRequest](https://developer.chrome.com/docs/extensions/reference/api/webRequest),
[optional permissions](https://developer.chrome.com/docs/extensions/reference/api/permissions),
[session storage](https://developer.chrome.com/docs/extensions/reference/api/storage).
